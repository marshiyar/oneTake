# Status

What the app does at this revision, feature by feature. "Works" means wired into the running Linux, macOS and Windows app
and covered by tests; "partial" means some of it is there; "stub" means the call exists but throws or does nothing;
"missing" means there is no code for it.

The desktop entry point (`Sources/MpvfxDesktop/main.swift`) passes `RuntimeDesktopBackend` (`Sources/MpvfxBackend/`) to
every shell, so projects, saving, media import, the media bin, libraries, thumbnails, waveforms and render output go
through the real runtime. Only publishing is refused on purpose ("Publishing is not supported in the native app").
`NotImplementedBackend` remains in `MpvfxDesktopCore` as a test double only.

| Visual effects / color grading / LUTs | works: the clip grade (presets, intensity, primary, wheels, 7 curve modes, secondaries, `.cube` LUT, vignette, grain) and its 18 stylize effects render in preview and export. On macOS they run on the GPU: the grading shader and its blur, bloom and Kuwahara passes are Metal compute kernels (`Sources/MpvfxMetal/Shaders/MpvfxColor.metal`, a SwiftPM resource compiled into the bundle's `default.metallib`, with the bundled source compiled at runtime if that is missing; uniform layout in `MpvfxColorShared.h`; 3D texture LUT, 1D curve textures), within 1 level of the CPU reference for every deterministic control, and 1080p with Kuwahara + crosshatch + ASCII + grade in about 17 ms per frame on an Apple M4 (measured on an M4 runner; the 30 fps budget of `testPerformance1080pHeavyEffects` is asserted only on a real Apple GPU: GitHub's hosted macOS runners (macos-15 and xcode-27, macOS 27) have a virtual GPU, `Apple Paravirtual device`, where the same stack takes about 37 ms and the test only renders, times and forbids a CPU fallback, owner decision 2026-10-19). Linux grades on the GPU through Vulkan compute (`Sources/CMpvfxVulkan`, the system loader opened at run time) and Windows through Direct3D 11 compute (`Sources/CMpvfxWin32/d3d11_grade.cpp`, HLSL compiled by d3dcompiler_47 and cached); both run kernels that `scripts/gpu/gen-compute-shaders.py` generates from the Metal shading body (committed GLSL, HLSL and SPIR-V words; every float operation without contraction, sin/cos computed in-shader to within an ulp of the CPU's). `ColorRendering.shared` picks Metal, Vulkan or Direct3D 11, else the CPU; software devices (lavapipe, WARP, and the Microsoft Basic Render Driver that GPU-less Windows machines report as a hardware adapter: DXGI_ADAPTER_FLAG_SOFTWARE or PCI id 1414:008c, `GPUPolicyTests`) only with `MPVFX_GPU=software`, and `MPVFX_GPU=0` forces the CPU. Without a usable device the CPU implementation of the same shader grades, and it is the reference every GPU path is tested against: on Mesa lavapipe the Vulkan kernels, and the Direct3D HLSL source through glslang, pass every case of the Metal parity test at its thresholds, most cases bit-exact (`ComputeColorRendererTests`, `HLSLSourceOnVulkanTests`); the Direct3D 11 path itself is tested on WARP by the Windows CI job only (not run on Linux), where every case of the parity test, `testAlternatingFrameSizes` included, matches the CPU reference (blur, bloom, strong blur and blur + Kuwahara bit-exact; OneTake-app/mpvfx-windows-ci run 39144316989). Both compute hosts run one multipass plan (`Sources/CMpvfxColorShared/include/MpvfxGpuPlan.h`: pass order, buffer roles and sizes, threadgroup counts, parameters by value; `GPUPlanTests` on Linux). `swift run -c release MpvfxColorBench` times CPU vs GPU at 1080p and 4K. The preview caches raw decoded frames and grades them off the main thread (`PreviewGrader`): a draw never waits for a grade, it shows the clip's latest finished look and asks for the current one; rapid edits coalesce to the newest value; pictures are graded at their on-screen size (a 4K frame shown at 1080p is reduced once and the reduced copy reused); on Metal the source frame stays resident on the GPU between parameter changes, so a slider move re-runs only the kernels; on the CPU shader (no GPU) a change is first shown as a 960x540 draft, then the full display-size grade. Grade edits never restart decoders or flush the frame cache (`PreviewRapidGradeTests`: 100 changes, `PreviewEditLatencyTests`: edit-to-draw latency per control); export pre-renders graded clips losslessly, then composites them. The inspector's curve graph evaluates the curve with the renderer's own normalization and monotone cubic (`Sources/MpvfxShared/Project/GradeCurve.swift`) and clips its drawing to the graph, so the line shown is the curve applied, inside 0…1 (`CurveGraphTests`, `PreviewGradeTests.testPreviewAppliesTheCurveTheGraphDraws`). Other effect ids are still refused by export.
